# 模块边界：AuthZ 与 AuthN、Identity、Suggest

> 状态：已实现 · 本轮代码已实现，生产数据切换与业务验收另行记录。

| 事实或责任 | 拥有者 | AuthZ 的协作边界 |
|---|---|---|
| 身份认证、会话、令牌 | AuthN | 使用可信认证结果形成 Subject |
| 用户存在性与状态 | Identity | Assignment 写入通过 resolver 校验 |
| 监护关系 ProfileLink | Identity 及业务调用方 | 不转换为 IAM 动作授权 |
| 医生管理关系 clinician_relation | QS | QS 查询并检查受试者范围 |
| 测评状态、机构与重试资格 | QS | 通过 retry/force_retry 动作授权后继续检查 |
| Role、Grant、Assignment、Resource | AuthZ | 维护授权事实与判定 |
| 搜索结果与查询约束 | Suggest | 按动作能力执行自身查询规则 |

IAM 不回调业务库加载对象，不维护资源属性模式，不接收业务对象属性进行条件求值。医生身份不补足结果读取权限；拥有结果权限也不绕过医生与受试者关系。

服务身份决定可调用哪些 RPC、可管理哪些 Assignment。Subject 决定正在判定哪个用户的角色授权；二者不能互相替代。

业务对象不存在、跨机构、无管理关系或状态不允许由业务系统拒绝；缺少动作权限由 AuthZ 或消费者使用有效快照拒绝。参与者、监护人自服务保持独立业务入口。

新增业务动作需注册目录、配置直接 Grant、明确调用入口及业务数据范围并添加正反测试。Scope 不在本轮引入。详见 [领域模型](01-领域模型设计.md) 与 [维护手册](08-条件授权退役维护手册.md)。
