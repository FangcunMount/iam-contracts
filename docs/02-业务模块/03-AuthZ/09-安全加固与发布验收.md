# 统一授权空间：切换与发布验收

> 状态：已实现 · 代码与离线工具已落地，生产发布与外部链路仍需单独验收。

IAM Go 模块为 v5，AuthZ REST/gRPC 为 v4，AuthN REST/gRPC 为 v3。Identity、IDP 和 JWKS 地址保持现有协议版本。服务端、SDK、QS、前端和事件配置必须配套发布；切换要求全员重新登录。

## 权限边界

角色名称全局唯一，关联使用 RoleID。`management_protection` 只控制授权管理，不参与判定请求、缓存键或版本分区。

受保护角色及其 Assignment、Grant、Inheritance 的管理需要原操作权限和 `manage_protected`。普通角色不能继承受保护角色，也不能通过资源或动作通配符获得敏感能力。敏感能力包括角色保护管理、资源目录写入和档案全量访问。普通管理查询隐藏受保护对象，按 ID 查询不可见对象返回 404。

Suggest 的全量列表和全量手机号检索分别使用 `list_all`、`search_by_mobile_all`；普通范围仍由操作人、业务 OrgID 和关联档案限制。

## 数据预检与迁移

迁移 31 增加保护属性；迁移 32 删除历史授权分区，保留角色 ID 和有效关系，并将策略版本收敛为主键 1 的全局记录。初始版本为历史最大版本加一，溢出即拒绝。

离线工具只读预检扫描活跃及历史记录，检查名称冲突、未知历史域、非法引用、继承图、敏感授权和 GrantKey。未知域、冲突、非法引用或普通角色敏感授权均阻止迁移，不能通过自动提升保护等级消除问题。

```sh
iam-maintenance tenant-retirement preflight > preflight.json
iam-maintenance tenant-retirement prepare --fingerprint <preflight-fingerprint> > preparation.json
```

连接使用部署环境中的 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_DATABASE`。报告包含主体、角色、资源与动作；不包含令牌或私钥。准备前必须完成数据库备份并停止全部授权写入。

准备在事务内再次校验指纹，执行固定改名、GrantKey 更新和档案全量能力补充。准备后的任意授权事实写入都会通过数据库触发器清除准备凭据；迁移 32 拒绝无凭据的非空数据库。重复准备仅在指纹仍对应同一事实时成功。迁移成功后删除临时触发器及凭据表。

空库初始化同样按“迁移到 31 → 预检和准备 → 迁移到 32 → 执行当前 bootstrap”执行，避免历史初始化记录绕过预检。生产升级不执行 bootstrap。

## 登录状态清理

先启用新签名密钥，再通过现有密钥生命周期能力强制退役全部旧验签密钥，保留审计记录。所有签发与会话写入停止后运行：

```sh
iam-maintenance purge-login-state > login-state-preview.json
iam-maintenance purge-login-state --apply --confirm PURGE_IAM_LOGIN_STATE > login-state-result.json
```

工具仅扫描 IAM 的 Session、用户会话索引、登录身份会话索引、RefreshToken、刷新重放标记和访问令牌撤销标记，分批 UNLINK。输出固定状态族与计数，不输出键名或令牌，不清空共享 Redis。微信服务令牌及其他业务缓存不在清理范围。

## 固定切换顺序

1. 停止外部流量、授权写入、令牌签发和相关消费者；记录当前镜像 SHA、配置及迁移版本，完成备份和恢复演练。
2. 执行数据库预检、准备及迁移，核对角色 ID、授权对照和全局版本。
3. 启用新签名密钥，强制退役旧验签密钥；清理旧登录状态。
4. 部署 IAM v5、配套 QS 与前端，更新事件主题 `iam.authz.version.v2` 和事件类型 `iam.authz.version_changed.v2`，停止全部旧实例。
5. 清理进程、分布式及代理中的 JWKS、验证结果和授权快照缓存。QS 快照键只包含用户和应用，全局版本通知淘汰所有较低版本快照。
6. 验证旧 AccessToken 本地及远程拒绝、旧 RefreshToken 无法刷新、旧 Session 不可用；验证新登录 → IAM 访问 → QS/Collection 授权 → 刷新 → 撤销。
7. 恢复流量，观察拒绝分类、登录失败、策略版本滞后、新鲜度及缓存更新指标。

IAM 资源访问固定使用部署受众 `iam-api`；QS 和 Collection 分别使用 `qs-api`、`collection-api`。没有关闭受众或角色保护校验的兼容开关。

## 验收与回滚

验收分别记录：IAM 全仓与 SDK 测试、调用方测试、缓存/runtime race、API 合约、文档检查、MySQL 8 升级和空库初始化、备份恢复，以及生产镜像/数据库/健康度/外部链路证据。单仓测试通过不能替代接入方或生产验证。

回滚恢复旧版本、配套配置和授权数据库备份。迁移 32 的 down 操作明确拒绝猜测原域归属。切换后有授权写入时先导出审计差异；回滚仍要求重新登录，不恢复旧 Session/RefreshToken，不重新启用已退役密钥。
